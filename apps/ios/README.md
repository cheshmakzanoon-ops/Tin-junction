# Tin Junction native engineering harness

This directory is the SwiftUI application shell, not a finished train game. It hosts the locally bundled Three.js renderer, validates a small diagnostic bridge, observes public Duo geometry/hinge APIs, and supplies XCTest targets. It requires Xcode 27.1 and the iOS 27.1 SDK. Source existence does not mean these targets have compiled or passed; inspect the current main commit's `iOS Simulator` workflow and evidence records.

## Reproduce the native check

From repository root on the documented macOS runner or a Mac with the same installed toolchain:

```bash
npm ci
npm run bundle:ios
bash tools/ios/install-xcodegen.sh
.tools/xcodegen-2.46.0/xcodegen/bin/xcodegen generate --spec apps/ios/project.yml
export DEVELOPER_DIR=/Applications/Xcode_27.1.app/Contents/Developer
mkdir -p artifacts/ios
xcrun simctl list --json > artifacts/ios/simulator-inventory.json
node tools/ios/select-duo.mjs artifacts/ios/simulator-inventory.json
```

Read the selected UDID, set `TIN_SIMULATOR_UDID` to that exact value, boot it with `xcrun simctl boot "$TIN_SIMULATOR_UDID"` only if its reported state is `Shutdown`, then run:

```bash
bash tools/ios/test-simulator.sh
```

The GitHub workflow performs these steps automatically without signing. `project.yml` is authoritative; generated `TinJunction.xcodeproj` is not committed. `Resources/WebAssets` is generated by `npm run bundle:ios`; never hand-edit its output or add `.gitkeep`/README files inside it.

## Source map

| File | Responsibility |
| --- | --- |
| `TinJunctionApp.swift` | Application/scene entry point; no singleton game world |
| `RootView.swift` | Explicit harness diagnostics, local view bounds, reserved regions, hinge observations, scene phase |
| `Platform/NativeViewport.swift` | Logical-point viewport payload; no guessed device dimensions |
| `Web/EngineWebView.swift` | WKWebView setup, exact navigation policy, main-frame script-message registration |
| `Web/BundleResourcePolicy.swift` | Scheme/host/method/path/extension/size policy and canonical bundle containment |
| `Web/BundleSchemeHandler.swift` | Read-only local resource delivery; synchronous harness implementation |
| `Web/EngineHostModel.swift` | Ready/bootstrap/lifecycle/viewport delivery, recoverable-context-loss transport, handshake deadline and bounded content-process reload |
| `Bridge/BridgeEnvelope.swift` | Version/type/identifier/object/64 KiB diagnostic input validation |
| `TinJunctionTests/` | Policy/bridge/viewport/bundle tests; not a physical-device certification |
| `TinJunctionUITests/` | Packaged WebKit handshake, rotation/foreground host survival, screenshots |

There is no native save store, production audio, haptics engine, purchase flow, app icon, release entitlement set, signing configuration, or public release automation yet. The current privacy manifest describes this deliberately minimal scaffold; audit it again whenever APIs/dependencies or data handling change.

See [Duo platform contract](../../docs/architecture/DUO_PLATFORM.md) and [native CI runbook](../../docs/operations/IOS_CI.md). In particular, iPhone-family targeting is not proof of Duo-only commercial distribution.
